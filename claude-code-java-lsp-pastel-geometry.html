What / Why
02 / 11

什么是 LSP？为什么 Claude Code 需要它？

LSP（Language Server Protocol）让编辑端和语言分析端分工协作：Claude Code 发请求，语言服务器返回定义、引用、诊断等结构化结果。

没有 LSP

Claude 仍然很会读代码，但在 Java 这种强类型、多模块工程里，纯文本搜索经常不够稳。

开启 LSP

语义级导航、错误诊断、实现类查找、调用层级分析都会明显更精准、更工程化。

一句话：不开 LSP 时，Claude 更像聪明的代码阅读者；开了 LSP 后，它更像接上 IDE 智能内核的工程助手。

Before / After
03 / 11

不开 LSP vs 开启 LSP

不开 LSP

  • 能找到很多“像定义”的地方，但不一定是准确目标
  • 理解代码意图可以，但实时类型错误拿得不够快
  • 多模块 Maven / Gradle 项目中，文本搜索容易失真
  • Refactor 时缺少精确引用关系，风险偏高

开启 LSP

  • 精确跳转定义、查找引用
  • 获取实时类型诊断和错误信息
  • 查看接口实现类与调用层级
  • 列出 workspace symbols，导航更像 IDE
Architecture
04 / 11

LSP 工作机制：三层协作

1

Claude Code 内建 LSP tool

发出“定义 / 引用 / 诊断”等请求。

2

Code intelligence plugin

Java 对应官方插件 jdtls-lsp。

3

语言服务器 binary

系统里的 jdtls 真正负责分析 Java workspace。

实际流程

打开 Java 项目 → Claude Code 加载 jdtls-lsp → 插件启动系统里的 jdtls → jdtls 分析 workspace → Claude Code 请求定义 / 引用 / 诊断 → 用于导航、分析与编辑
Best Practice
05 / 11

最佳实践：优先走官方路径

推荐方案

直接使用官方 jdtls-lsp 插件 + 系统里的 jdtls，而不是自己手写 .lsp.json。

为什么这样更优雅

  • 不用猜启动参数、通信方式、扩展名映射
  • 更少踩 PATH / command / workspaceFolder 坑
  • 跟官方维护路径一致，升级兼容性更好
7

统一安装节奏

安装 JDK → 安装 jdtls → 确认 PATH → 安装 jdtls-lsp → /reload-plugins → 在项目根目录启动 → 验证 LSP 生效。

多平台安装思路，核心流程一致

Linux

sudo apt install -y openjdk-21-jdk sudo apt install -y jdtls which jdtls

macOS

brew install openjdk@21 brew install jdtls which jdtls

Windows

winget install Microsoft.OpenJDK.21 下载并解压 jdtls 配置 jdtls.cmd + PATH

共同收尾动作

Claude Code 中安装 jdtls-lsp /reload-plugins 在项目根目录重启会话
Verification
07 / 11

怎么确认 LSP 真的生效了？

先看插件状态

/plugin 检查 jdtls-lsp 是否启用 检查是否出现 Executable not found in $PATH

再做功能测试

  • 找一下 UserService 的定义
  • 列出 OrderController 的所有引用
  • 看看当前工程有哪些 Java 类型错误
  • 找一下这个接口有哪些实现类

如果这些操作明显比纯文本搜索更准、更稳，说明 LSP 基本已经接通。

Troubleshooting
08 / 11

常见问题排查

1

Executable not found in $PATH

检查 which jdtls / where.exe jdtls 是否有输出，并确保命令可执行。

2

插件装了但像没生效

先 /reload-plugins，再在 /plugin 查看状态和错误信息。

3

找定义不够准

确认在项目根目录启动，Maven / Gradle 配置完整，JDK 版本匹配项目要求。

4

诊断信息不完整

先保证项目本身可构建：mvn compile 或 ./gradlew classes。

Practical Checklist
09 / 11

一页带走：最实用检查清单

01 官方优先

别手写 .lsp.json，先用官方插件链路。

02 命令可执行

jdtls --help 至少要能正常返回。

03 根目录启动

尤其是多模块项目，workspace 根目录非常关键。

04 项目先健康

先把依赖和构建跑通，LSP 才有高质量语义信息。
