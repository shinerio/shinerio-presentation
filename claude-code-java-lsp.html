什么是 LSP？

LSP (Language Server Protocol) 是一种标准通信协议，让"代码编辑端"与"语言分析端"分工合作。

工作原理：

客户端发起请求（查找定义、引用、诊断错误）→ 语言服务器返回结构化结果

  • 编辑器负责 UI 和用户交互
  • 语言服务器负责代码分析和智能提示
  • 通过 JSON-RPC 标准协议通信
02

❌ 不开 LSP 的问题

  • 能找到"像定义"的地方，但一定准确
  • 能读懂代码意图，但缺乏实时诊断
  • 多模块项目中依赖文本搜索
  • Refactor 时缺少精确引用信息

✅ 开启 LSP 后的增强

  • 精确跳转到定义、查找引用
  • 获取实时类型诊断和错误信息
  • 查看接口的所有实现类
  • 分析调用层级、列出 workspace symbols

总结：不开 LSP 时，Claude 是聪明的代码阅读者；开了 LSP 后，它是接上了 IDE 代码智能的工程助手。

03

LSP 工作机制

Claude Code 通过三层协作实现 LSP 能力：

# 1. Claude Code 内建的 LSP tool const lspTool = require('@anthropic-ai/claude-code') # 2. Code intelligence plugin (Java 对应 jdtls-lsp) const plugin = install('jdtls-lsp') # 3. 系统里的语言服务器 binary (Java 对应 jdtls) $ which jdtls /usr/bin/jdtls

流程：打开 Java 项目 → 加载插件 → 启动 jdtls → 分析 workspace → 通过 LSP tool 请求信息

04

为什么选择官方插件？

对于 Java 这种"官方已覆盖语言"，最优雅的方式是直接使用官方 jdtls-lsp 插件 + 系统里的 jdtls。

优势：

  • 更稳：不用猜启动参数、通信方式、扩展名映射
  • 更少坑：避免 command 配错、PATH 问题等常见问题
  • 更符合官方维护路径：未来升级时兼容性更好
05

整体安装流程的七步曲

Step 1: 安装 JDK Step 2: 安装 jdtls Step 3: 确认 jdtls 在 PATH 中 Step 4: 在 Claude Code 安装官方插件 jdtls-lsp Step 5: 执行 /reload-plugins Step 6: 在 Java 项目根目录启动 Claude Code Step 7: 验证 LSP 是否生效

无论哪个平台，推荐流程一致。接下来我们看看每个平台的具体步骤。

06

Linux 安装步骤

第 1 步：安装 JDK

sudo apt update && sudo apt install -y openjdk-21-jdk java -version

第 2 步：安装 jdtls

sudo apt install -y jdtls which jdtls

第 3 步：如果仓库没有 jdtls，手动安装（详见完整报告）

第 4 步：在 Claude Code 中搜索并安装 jdtls-lsp，然后执行 /reload-plugins

macOS 安装步骤

第 1 步：安装 JDK

brew install openjdk@21 echo 'export PATH="$(brew --prefix)/opt/openjdk@21/bin:$PATH"' >> ~/.zshrc source ~/.zshrc

第 2 步：安装 jdtls

brew install jdtls which jdtls

第 3 步：如果需要，手动安装（详见完整报告）

第 4 步：在 Claude Code 中安装 jdtls-lsp，然后 /reload-plugins

08

Windows 安装步骤

第 1 步：安装 JDK

winget install Microsoft.OpenJDK.21

第 2 步：手动安装 jdtls

下载并解压 jdtls 到 %USERPROFILE%\tools\jdtls

第 3 步：创建 jdtls.cmd

创建启动脚本（详见完整报告）

第 4 步：加入 PATH

[Environment]::SetEnvironmentVariable("Path", $env:Path + ";$HOME\bin", "User")
09

验证是否成功

查看插件状态：

/plugin

确认 jdtls-lsp 是否启用，检查是否有 Executable not found in $PATH 错误。

功能测试：

  • "找一下 UserService 的定义"
  • "列出 OrderController 的所有引用"
  • "看看当前工程有哪些 Java 类型错误"
  • "找一下这个接口有哪些实现类"

✅ 如果这些操作明显比纯文本搜索更准，说明 LSP 已经生效。

10

常见问题排查

问题 1：Executable not found in $PATH

检查 which jdtls 或 where.exe jdtls 是否有输出，确保 jdtls 命令可以正常执行。

问题 2：插件装了但感觉没生效

执行 /reload-plugins，在 /plugin 中查看状态和错误信息。

问题 3：能打开项目项目，但找定义不够准

确认在项目根目录启动（包含 pom.xml 或 build.gradle），检查 Maven/配置是否完整。

最佳实践建议

  • 优先走官方路径：不要手写 .lsp.json，直接用官方 jdtls-lsp + jdtls
  • 确保 jdtls 稳定：jdtls --help 必须能正常执行
  • 在项目根目录启动：多模块项目在 workspace 根目录启动
  • 保证项目健康：先让项目能正常构建，LSP 诊断质量会更好
